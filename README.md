# ذاكرة حائل — نسخة Vercel

هذه النسخة تحوّل الجزء الخلفي من PHP/MySQL إلى Node.js وSupabase، وتحافظ على المتحف والمجسمات الثمانية المحلية والعروض الثلاثة المتصلة. لا تحتاج XAMPP. أُعد الكود واختُبر محليًا، لكن لم يُنشَر في حساب Vercel ولم يُربط بمشروع Supabase حقيقي بعد.

## الخطوة 1: إنشاء Supabase

1. أنشئ مشروعًا جديدًا مخصصًا للمتحف على https://supabase.com/dashboard .
2. افتح SQL Editor، وانسخ محتويات `supabase/schema.sql` كاملة ثم اضغط Run. يُنشئ الجداول ومساحة الصور الخاصة.
3. من إعدادات المشروع احصل على Project URL، ثم من API Keys أنشئ/انسخ Secret key (يبدأ عادة بـ `sb_secret_`). احتفظ به لإعداد Vercel فقط. يمكن استخدام legacy service_role بدلًا منه إن لزم.
4. لا تضع المفتاح في HTML أو JavaScript داخل public ولا في GitHub. لا تحتاج الواجهة إلى أي مفتاح Supabase.

## الخطوة 2: إنشاء حساب المدير والباحث

1. افتح Authentication → Users في Supabase ثم أضف مستخدمًا ببريدك وكلمة مرور قوية، مع تأكيد البريد من لوحة الإدارة عند إنشاء المستخدم.
2. افتح `supabase/assign-role.sql`، واستبدل `CHANGE_ME@example.com` **في الموضعين** بالبريد الذي أنشأته، واستبدل الاسم المعروض.
3. شغّل SQL في SQL Editor. يجب أن تُظهر نتيجة الاستعلام الأخير حسابًا بدور admin. إذا أعادت صفر صفوف، صحّح البريد أو أنشئ الحساب أولًا.
4. لإنشاء باحث كرّر الخطوات ببريد جديد، واستبدل `admin` بـ `researcher`.
5. لتعطيل وصول حساب موجود، غيّر `active` إلى false في جدول hm_profiles. لا يكفي إخفاء رابط اللوحة؛ الصلاحيات تُفحص على الخادم في كل طلب.

لا توجد كلمات مرور افتراضية، ولا تسجيل ذاتي لحسابات الباحثين أو المديرين. يمكن تغيير كلمة المرور من إدارة المستخدمين في Supabase.

## الخطوة 3: رفع المشروع إلى GitHub

1. فك الضغط عن الملف.
2. أنشئ مستودعًا جديدًا وارفع **محتويات مجلد hail-memory-vercel**، بحيث يظهر `package.json` و`vercel.json` مباشرة في جذر المستودع.
3. ارفع مجلدات public وapi وlib وscripts وsupabase، وملفي package.json وpackage-lock.json مع بقية ملفات المشروع.
4. لا ترفع node_modules أو dist أو .env.local. ملفات GLB موجودة داخل public/assets/models وحجمها مناسب للرفع المعتاد.

## الخطوة 4: النشر على Vercel

1. افتح https://vercel.com/new واختر مستودع GitHub.
2. Framework Preset: **Other**.
3. Root Directory: جذر المستودع؛ إذا رفعت المجلد داخل مستودع آخر فاختر `hail-memory-vercel`.
4. الإعدادات الموجودة في vercel.json:
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - Node.js: `22.x` (محدد في package.json)
5. أضف Environment Variables التالية، لقسمي Production وPreview إن أردت اختبار المعاينات:

| المتغير | القيمة |
|---|---|
| `SUPABASE_URL` | رابط مشروع Supabase الخاص بالمتحف |
| `SUPABASE_SECRET_KEY` | Secret key من Supabase؛ خاص بالخادم |

إذا استخدمت المفتاح القديم، استخدم `SUPABASE_SERVICE_ROLE_KEY` بدل SUPABASE_SECRET_KEY؛ لا تضف المفتاحين معًا. لا تضع بادئة NEXT_PUBLIC أو VITE لهذه القيم.

6. اضغط Deploy. إذا أضفت المتغيرات بعد النشر، نفّذ Redeploy.
7. افتح الرابط الذي يعطيك Vercel:
   - `/` المتحف.
   - `/contribute.html` إرسال المشاركات.
   - `/login.html` تسجيل دخول المدير والباحث.
   - `/admin/dashboard.html` لوحة المدير.
   - `/researcher/dashboard.html` لوحة الباحث.

واجهة المتحف تظهر حتى قبل ضبط Supabase؛ حفظ المشاركات والدخول واللوحات تحتاج الخطوات كاملة. يُعاد توجيه روابط لوحات PHP القديمة إلى صفحات HTML الجديدة.

## تجربة التشغيل الفعلية

1. أرسل حكاية من 20 حرفًا أو أكثر وصورة صغيرة من صفحة ساهم معنا. دوّن رقم المتابعة.
2. ادخل كباحث: سترى الحكاية دون بريد صاحبها، ويمكنك حفظ ملاحظتك الخاصة.
3. ادخل كمدير: اعتمد المشاركة. تظهر الآن أسفل المتحف للزوار.
4. أعدها إلى المراجعة أو ارفضها؛ يجب أن تختفي من العرض العام.
5. افحص رابط الصورة بحساب مجهول قبل النشر؛ يجب أن يعيد 404. بعد النشر يمكن للزوار رؤيتها.
6. تأكد من عدم إظهار اسم المساهم إذا لم يوافق على نشره.

## التخزين والصلاحيات

- `hm_contributions`: النصوص والبيانات وحالة المراجعة والموافقة.
- `hm_profiles`: أسماء فريق العمل وأدوارهم وتفعيل حساباتهم.
- `hm_notes`: ملاحظات مرتبطة بالباحث والمشاركة.
- `hm_sessions`: بصمات رموز جلسات عشوائية؛ لا تُخزن كلمات المرور هنا. تنتهي الجلسة بعد 30 دقيقة دون نشاط، وبحد أقصى 8 ساعات.
- `hm_rate_buckets`: حدود الإرسال ومحاولات الدخول، بشكل مشترك بين وظائف Vercel.
- كلمات المرور يديرها Supabase Auth.
- الصور تُحفظ داخل bucket خاص اسمه `hail-memory-private`. لا تجعله public، ولا تضف له سياسة وصول عامة. الخادم يتحقق من الصلاحية قبل تقديم الصورة من `/api/image`.

RLS مفعل على جداول التطبيق، وصلاحيات anon/authenticated مسحوبة؛ كل الوصول يمر عبر وظائف Node التي تتحقق من الأدوار. مفتاح Supabase السري يُستخدم على الخادم فقط. هذا مقصود، وليس نقصًا في سياسات الواجهة.

حد الصورة **2 ميجابايت** لتبقى طلبات JSON مع Base64 دون حد Vercel البالغ 4.5 ميجابايت. تُفحص الصورة وتُعاد كتابتها بصيغة WebP، وتُزال بياناتها الوصفية، ويُخفض أكبر بُعد إلى 1600 بكسل. ملفات GLB الثابتة مستقلة عن هذا الحد وتُقدم كأصول ثابتة.

## التشغيل المحلي

ثبّت Node.js 22، ثم من داخل مجلد المشروع:

```bash
npm ci
```

انسخ `.env.example` باسم `.env.local` وأدخل بيانات مشروع Supabase، ثم:

```bash
npm run dev
```

افتح http://localhost:3000 . الخادم المحلي يخدم الصفحات وواجهات API نفسها، ولا يخدم ملفات الإعداد أو SQL. لمعاينة المتحف فقط يمكنك تشغيله دون المتغيرات؛ العمليات المرتبطة بالبيانات تُظهر رسالة إعداد واضحة.

```bash
npm test
npm run build
```

## الهيكل

- `public/`: الصفحات وملفات العرض والمجسمات التي يجوز تقديمها للزوار.
- `api/*.js`: تسع وظائف Node.js لـVercel.
- `lib/core.js`: التحقق من الطلبات والصلاحيات، الاتصال بـSupabase، وفحص الصور.
- `supabase/schema.sql`: تجهيز قاعدة البيانات ومساحة التخزين.
- `supabase/assign-role.sql`: تعيين دور بعد إنشاء حساب المستخدم.
- `scripts/build.mjs`: نسخ الأصول العامة إلى dist فقط؛ الملفات الخلفية والإعدادات لا تُنشر كملفات ثابتة.
- `scripts/dev.mjs`: خادم التطوير المحلي.
- `tests/api.test.mjs`: اختبارات صلاحيات وتدفق الطلبات، مع محاكاة Supabase.
- `vercel.json`: إعداد البناء ووظائف الخادم وترويسات الأمان.

## ملاحظات الإطلاق

هذه نسخة جديدة تحتاج قاعدة Supabase جديدة؛ لا تنقل تلقائيًا بيانات MySQL من النسخة السابقة. إن كان لديك مساهمات حقيقية في MySQL، صدّرها وانقلها قبل تبديل موقع منشور. لم تكن هناك بيانات مستخدمين مرفقة بهذه الحزمة.

تراخيص المجسمات موضحة في `public/sources.html`؛ بعض النماذج مقيّد بالاستخدام غير التجاري. سياسة الخصوصية وبيانات الجهة المشغلة يجب أن تناسب استخدامك قبل استقبال بيانات حقيقية. لا تُنشر إعدادات سرية أو بيانات أصحاب المساهمات في مستودع GitHub.
